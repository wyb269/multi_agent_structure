# 智能体之间的数据交付标准

## 是什么

让一个智能体的输出成为下一个智能体可检查的输入。可以把它理解为函数之间约定好的输入、输出类型：不仅要交付结论，还要交付任务编号、执行状态、证据和错误信息。

## 与协同架构的关系

流水线、主子、并行等架构决定谁先做、谁后做；数据交付标准决定交接时传递什么，以及接收方如何判断结果是否可用。它不是独立的协同架构。

## 原对话中的例子

政策检索智能体可以返回结构化结果：

```json
{
  "task_id": "task-001",
  "agent": "policy_researcher",
  "status": "completed",
  "result": {
    "summary": "政策检索结果",
    "sources": [
      {
        "title": "文件名称",
        "url": "https://example.org/document",
        "verified": false
      }
    ]
  },
  "errors": []
}
```

示例 URL 是占位地址，`verified` 只有经过真实来源核验后才能设为 `true`。接收方可先检查 `status`、必填字段和证据，再决定继续、重试或交由人工处理。
