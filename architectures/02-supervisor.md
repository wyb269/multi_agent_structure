# Supervisor / Manager-Worker：主子智能体架构

(通用复杂任务的优先选择)

集中控制：主控负责任务分配和最终输出

这是目前非常典型的多智能体组织方式。

它类似企业的项目经理管理多个专业团队。

**主智能体（Supervisor）主要负责：**

- 理解用户目标，进行任务拆解。
- 根据任务选择合适的子智能体。
- 决定子任务执行顺序，必要时并发执行。
- 检查子智能体结果是否满足目标。
- 汇总结果，并决定是否继续调用其他智能体。

**子智能体（Worker）主要负责：** 在自己的专业领域执行明确的任务，例如数据库查询、代码生成、政策检索或文档审查。

例如，用户输入：

> 帮我分析某政企项目的安全风险，形成一份正式整改报告，并核查相关法规依据。

Supervisor 可能执行以下过程：

- 先派安全分析 Agent 整理漏洞和风险。
- 同时派法规检索 Agent 查找适用规定。
- 将两个结果交给写作 Agent。
- 调用审查 Agent 核对技术措施与政策依据。
- 如果审核不通过，再指派相关 Agent 修改。

与 Pipeline 最大的区别是：**Pipeline 的路径通常事先确定，而 Supervisor 可以根据任务内容和中间结果动态选择下一步。**

OpenAI 将这种组织方式称为 Manager / Agents as Tools：主智能体通过调用专业智能体完成任务，但始终保留对最终回答的控制权。

**优点：** 职责清晰、子智能体容易复用、便于扩展专业能力，适合统一对外输出。

**缺点：** 主控可能成为性能和决策瓶颈；任务拆解不合理会拖累整体效果；主控反复调用子智能体可能增加 Token 消耗及延迟。

**适用场景：** 企业智能助手、复杂公文写作、软件开发 Agent、自动化安全分析以及多工具协作平台。

## 对话中的产品案例

Claude Research：主 Agent 委派子 Agent 研究并汇总结果。[官方工程文章](https://www.anthropic.com/engineering/multi-agent-research-system)

Lovable：主 Agent 委派并行只读子 Agent，代码修改由主 Agent 负责。[官方文章](https://lovable.dev/en/blog/subagents-in-lovable)
