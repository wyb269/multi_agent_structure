# Pipeline：流水线架构

(入门最简单、工程可控性高)

固定顺序：A → B → C

**核心原理：** 将一个复杂任务分解为若干顺序固定的处理阶段。上一个智能体输出的结果，作为下一个智能体的输入。

例如，自动撰写政策分析文章：

1. 检索智能体：搜索中央及地方政策文件，提取可信来源。
2. 分析智能体：分析政策内容，提炼重点与关联关系。
3. 写作智能体：基于分析结果生成正式文章。
4. 审查智能体：检查引用、逻辑与公文格式。

其执行方式可以表示为：

\[
O_1=A_1(X),\quad O_2=A_2(O_1),\quad O_3=A_3(O_2)
\]

其中 \(X\) 是原始任务，\(A_i\) 是不同智能体，\(O_i\) 是各阶段输出。

**优点：** 结构简单、执行路径确定、易于调试、审计方便。每个阶段还能独立设置模型、提示词和输出格式。

**缺点：** 总耗时近似为各阶段耗时之和；前面步骤的错误可能向后传播；不能自然适应复杂的动态任务。想要返回修改上一环节，通常需要额外设计循环或分支。

**适用场景：** 固定的文档生成、ETL 数据处理、合同信息提取、报告生产和标准化审批前处理。

这一模式并不要求每个阶段都使用大语言模型。对于确定性的格式转换、计算和数据库操作，直接调用普通程序往往更可靠。
